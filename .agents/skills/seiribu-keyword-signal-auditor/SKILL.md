# Seiribu Keyword Signal Auditor

検索語の反復回数ではなく、検索者が使う言葉と記事が答える問題が明確につながっているかを監査する。本文の品質評価、全文リライト、順位の保証は行わない。構造や本文を変える必要がある場合は、判断を `seiribu-seo-editor` の PHASE 0 に渡す。

## 用語

- **検索ラベル**: 検索者の悩みを、そのまま又は自然な変形で受け止める語。title、H1、冒頭、主役H2、FAQ、表の項目名、内部リンクのアンカーに置く。
- **KW輪郭**: そのページが「誰の、どの状況の、何を知りたい検索」に答えるかが、検索結果と本文序盤で識別できる状態。
- **本文品質**: 根拠、実用性、独自の判断、読みやすさ。KW輪郭とは別に評価する。本文品質が高くても、KW輪郭が薄ければ狙ったクエリの候補になりにくい。

## 入力を集める

可能な範囲で、次をそろえる。

- 対象URL、slug、現行title、H1、導入、H2/H3、FAQ、内部リンクのアンカー。
- リライト前のtitle、H1、見出し、本文又は差分。なければSearch Consoleで過去に表示されたクエリ。
- Search Consoleのページ単位・クエリ単位データ。直近28日と前28日を基本に、公開又はリライトから90日未満なら公開以降の全期間も見る。
- 競合し得る自サイト記事のtitle、主KW、読後判断。カニバリと誤認しないために使う。

7日間で表示回数が1から数十件のデータは、方向の仮説には使っても、順位低下・サイト評価低下の断定根拠にはしない。新規記事にクエリがほぼ出ないときも、サイト全体の評価だけを原因にせず、クロール・インデックス・検索意図・ページ固有の検索ラベルを分けて確認する。

## 監査手順

1. **検索の約束を一文に固定する。**
   - `「実家の片付けで何から始めるか」を知りたい人が、最初の一手を決める記事` のように書く。
   - 主KWを1つ、準主KWを最大3つまでに絞る。年齢、続柄、感情、行動、状況などの修飾語はロングテール候補として分ける。
   - 別記事が主役にすべきクエリは `扱わないKW` に置く。
2. **クエリを役割で分類する。**
   - `主KW`: ページの約束そのもの。
   - `準主KW`: 主KWの自然な言い換え又は同じ検索意図の具体化。
   - `相談語`: `頭おかしい`、`一人っ子`、`夫` のような、検索者が実際に使う状況・感情の語。
   - `導線語`: 詳説せず、内部リンク先へ送るべき語。
   - `扱わないKW`: 別の読後判断を求める語。無理に受け入れない。
3. **検索ラベルの置き場を照合する。**
   - 主KWがtitleかH1のどちらかで明確か確認する。
   - 冒頭で検索者の疑問に直接答え、抽象語だけに言い換えていないか確認する。
   - 主KW又は最重要の準主KWを受け止める主役H2が1つあるか確認する。
   - 相談語を、答えられる範囲でH2、H3、FAQ、表のいずれかに自然に置けるか確認する。
   - 重要な内部リンクのアンカーが `こちら` や `詳しく見る` だけでなく、送り先の判断を表しているか確認する。
4. **旧版と現行版の損失を判定する。**
   - 削除された語が、単なる関連KWの散布だったのか、ページの検索意図を示すラベルだったのかを分ける。
   - 旧クエリに対する明確な答えが現行版に残っているかを確認する。答えがない語は戻さない。
   - 旧見出しをそのまま戻さず、現在の根拠と記事の役割に合う最小の置き場を決める。
5. **原因を切り分ける。**
   - `検索ラベル欠落`: 旧クエリ又は狙うクエリに対応するtitle/H1/主役H2/冒頭の答えが消えている。
   - `検索意図ずれ`: ラベルはあるが、記事の結論や読後判断がクエリと違う。
   - `競合又は役割不明`: 同じクエリを自サイトの複数記事が曖昧に受けている。
   - `評価待ち・データ不足`: ラベルと意図は明確だが、公開直後又は表示回数が少なすぎて結論を出せない。
   - 複数原因なら主因と副因を分ける。`サイト評価に時間がかかっている` は他の根拠を確認するまで仮説扱いにする。

## KW輪郭スコア

次の5層を各0から3で見る。合計は優先順位付けの補助であり、機械判定には使わない。

| 層 | 3点 | 1点 | 0点 |
| --- | --- | --- | --- |
| ページの顔 | title/H1で主KWと対象状況が明確 | 抽象的な言い換えのみ | 何の検索に答えるか不明 |
| 冒頭の答え | 冒頭で主KWの疑問に直接答える | 共感はあるが答えが遅い | 一般論から始まる |
| 構造の受け皿 | 主役H2が主KWを処理する | H2内に埋もれる | 受け皿がない |
| ロングテール | 答えられる相談語だけに自然な置き場がある | 語はあるが役割が曖昧 | 全て抽象語に吸収される |
| 役割の分離 | 他記事との境界と内部リンクが明確 | 一部で重複する | 複数記事が同じ語を取り合う |

- `13から15`: 保持。表示データを見ながら小さく補強する。
- `9から12`: 補強。title、冒頭、主役H2、FAQの順で最小パッチを検討する。
- `5から8`: 再設計。本文品質とは別に、検索の約束と構造を戻す。
- `0から4`: 処遇再判定。救うクエリと記事の役割を先に決める。

## 復元パッチの原則

- title、H1、冒頭、主役H2、FAQ、内部リンクのうち、最小限の場所だけを直す。
- 1記事に複数のロングテールを並列で取り込まない。最も近い1から3語だけを受け止め、残りは導線又は別記事にする。
- 生の検索語が強い言い方でも、読者の意図を失わない自然な表現にする。例として、`断捨離 頭おかしい` は否定語を煽りに使わず、「断捨離が極端に見えると感じるとき」のように問いと答えを成立させる。
- その語に本文で明確に答えられないなら、title・H2・FAQに戻さない。
- 同じ語をtitle、H1、全H2、FAQへ機械的に繰り返さない。KW密度や関連語数を合格基準にしない。
- `売る・残す・捨てる` はサイトの判断軸として使い、全記事の主KWを置き換える抽象語としては使わない。

## 禁止する判断

- 内容が良いことだけを理由に、KW輪郭不足を見逃さない。
- 平均掲載順位や少数インプレッションだけで、上昇・下降を断定しない。
- 旧記事に順位があったことだけを理由に、根拠のない見出しや無関係な関連KWを復活させない。
- 新規記事にクエリが出ない原因を、サイト全体の評価待ちだけに帰属させない。
- 検索ラベルを増やすために、別トピッククラスタをH2化しない。
