# Seiribu Rewrite Manager

このスキルは、セイリ部のリライト計画をぶれさせないために使います。役割は、どの記事を救うか、どの記事をロングテール化するか、どの記事を統合・noindex・削除候補にするかを判断し、Notionの進捗管理とそろえることです。

このスキルは本文執筆用ではありません。個別記事の検索意図、構成、本文リライトに入る場合は、`seiribu-seo-editor` に切り替えてフェーズゲートを守ります。

## 前提

- 現在の公開投稿は、固定ページを除いて26記事。
- サイトは1年以上放置されていた時期がある。
- 一時期、実家の片付け系からコレクタ向け整理記事へ方向が寄っていた。
- 現在の中心メッセージは `捨てる前に、売れるか確認。` に戻す。
- 戻した旧記事の多くは、現在の品質基準では低品質。
- 最近作成した高品質記事はインデックスされているため、主因は単純な技術的noindexではなく、記事品質・テーマ一貫性・救済対象の選別と見る。
- 旧記事をすべて無理にインデックスさせない。検索結果に残す理由がある記事だけを救う。

戦略全体、優先順位、処遇案を扱うときは、必要に応じて `references/rewrite-policy-2026q3.md` を読む。

## 作業手順

1. 依頼の種類を判定する。
   - 進捗管理・棚卸し: NotionのリライトDBを確認・更新する。
   - 優先順位づけ: 方針ファイルとリライトDBを参照する。
   - 単一記事の処遇判断: 記事を分類し、必要なら `seiribu-seo-editor` のPHASE 0へ渡す。
   - 構成・本文作成: このスキル単独で進めず、`seiribu-seo-editor` を使う。
2. 根拠を集める。
   - 必要に応じて、WordPressやサイトマップからタイトル、URL、スラッグ、公開日、更新日を確認する。
   - Search ConsoleのエクスポートやリライトDBからインデックス状況を確認する。
   - Notionに既存行があるか確認し、重複作成を避ける。
3. 記事を分類する。
   - `維持`: 最近作成またはリライト済みで、現方針に合う。
   - `リライト`: 現在のサイト方針に合い、救済価値がある。
   - `ロングテール化`: 狙いが広すぎるが、読者状況を絞れば残せる。
   - `統合候補`: 他記事と重複している、または単独では薄い。
   - `削除/noindex候補`: テーマから遠い、または救済コストに見合わない。
   - `要判定`: Search Console実績や本文確認が必要。
4. 優先度を付ける。
   - A: 中核クラスタ、過去流入の入口、収益導線に近い記事。
   - B: 補助記事、内部リンクの橋渡し、収益導線の支援記事。
   - C: テーマから遠い、一般論寄り、重複、戦略価値が低い記事。
5. Notionを更新する。
   - `リライト進捗`、`処遇案`、`優先度`、`トピクラ`、`インデックス`、`現在品質`、`メモ` を必要に応じて更新する。
   - 作業選定では `A優先_リライト順`、未登録確認では `未登録_確認対象`、処遇判断では `処遇案ボード`、全体進行では `リライト進捗ボード` を使う。
6. 本文制作の前で止める。
   - 個別記事を選んだら、選定理由を報告し、`seiribu-seo-editor` のPHASE 0へ進めるか確認する。

## 判断ルール

- 26記事を浅く触るより、救う記事を絞って深く直す。
- 最近インデックスされた記事を品質基準にする。
- ビッグKW狙いの記事は、実用的なロングテールへ寄せるか、インデックス対象から外す。
- 心理・家族記事は、共感だけで終わらせない。仕分け、家族確認、価値確認、売る・残す・処分の判断へ接続する。
- コレクタ向け要素は主軸にしない。捨てる前の価値確認に役立つ場合だけ `売れる物の整理` の一部として扱う。
- 隣接トピックは展開先であり、すべてをH2で厚く書く理由にはしない。
- WordPress上に存在するだけで「維持」や「入稿済み」と判断しない。

## トピック分類

- `実家の整理`: 片付けの始め方、順番、部屋ごとの進め方、家族との段取り。
- `売れる物の整理`: 売れる可能性のある品物、価値確認、品目別チェック、捨てる前の確認。
- `不用品の整理`: 買取不可、処分、回収業者、トラブル回避。
- `心理・家族`: 親が捨てさせてくれない、イライラ、兄弟分担、一人っ子、父親・夫の持ち物、感情面の詰まり。
- `横断`: 広すぎる概念。原則として、ロングテール化・統合・noindexの判定が必要。

## 出力方針

進捗管理や方針整理では、出力を短くまとめます。

- Notionで何を変更したかを言う。
- 優先順位づけでは、次に見るべき3から5記事を出す。
- 救済しない方がよい記事があれば明記する。
- 記事本文や長い構成案をチャットに貼らない。

古いSearch Consoleエクスポートや古いNotion情報に基づく場合は、必要に応じて「最新確認が必要」と明記します。
