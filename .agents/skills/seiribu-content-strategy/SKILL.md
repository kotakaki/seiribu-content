# Seiribu Content Strategy

このスキルは、セイリ部の記事を「情報を並べる記事」ではなく、「読者が売る・残す・処分する判断へ進む記事」にするために使います。

本文執筆用ではありません。記事制作に入る場合は `seiribu-seo-editor`、既存記事の処遇やNotion進捗管理は `seiribu-rewrite-manager` を使います。

## Core View

- ブログの価値は、AIで得られる一般情報ではなく、読者の混乱を現実の判断と行動へ変えること。
- セイリ部の中心メッセージは `捨てる前に、売れるか確認。`
- 読者は主に、親の家・実家の荷物整理に悩む40から60代の子世代。
- 読者の痛みは、量が多い、売るか捨てるかわからない、家族と揉める、自力では無理かもしれない、処分費が怖い、という複合不安。
- **収益化の最大のポイント（コア）** は、読者の「これ以上親と揉めたくない」「休日にゴミを運ぶ苦しみから解放されたい」という**ペインの限界点**を突き、「お金（費用）を払ってでも楽になる道（ショートカット）」を提示して財布の紐を解かせること。
- 収益は「集客」ではなく「送客」。記事を最後まで読ませる理想動線だけに頼らず、読者が絶望する（痛みに気づく）タイミングにのみ自然な出口を置く。

## Positioning

セイリ部は、整理の実体験を語る専門家ブログではなく、将来の実家整理に備える子世代の調査編集メディアとして扱います。

使う約束:

- `いきなり捨てない`
- `いきなり業者に投げない`
- `売る・残す・捨てるに分けてから、納得して片付ける`

避けること:

- 実体験がないのに `使ってみた` と書く
- 根拠のないランキングや高価買取の断定
- 読者の不安を煽って即申込へ押し込む
- 心理共感だけで終わり、実務判断へ接続しない
- ミニマリズムや自己啓発を主軸に戻す

## Article Role（記事の機能分化）

これまでの「全記事に同じコンセプト（3択仕分け、親とのコミュニケーション）をH2で盛り込む」設計は、金太郎飴化とSEOのトピックドリフトを招くため**厳格に禁止**します。
記事は以下の2つの役割（AとB）に冷酷に分断し、Aの記事にはBの要素（業者比較やタイパ要素）を一切書かせず、Bの記事にはAの要素（共感や背景解説）を書かせない「機能分化の壁」を設けます。

- **【A. 集客・情報記事（徹底的に1つの悩みに寄り添う）】**
  - 例：「実家片付け どこから」「親が捨てない」
  - ただ1つのKW（悩み）に対して泥臭い具体例と共感だけで回答する。H2に無理やり「売る・処分する」「業者の選び方」などの収益導線（コンセプト）を作らない。「この記事は自分の悩みをわかってくれている」と信用させた読者だけを、文末のリンクでBへ送る。
- **【B. 収益・行動記事（徹底的にタイパと一択に振り切る）】**
  - 例：「不用品回収業者の選び方」「着物買取の比較」
  - 共感や背景は不要。ここで初めて「フローチャート式提示」や「独自の比較軸での一択提示（選ばせないUX）」を爆発させ、「Aルートなら〇〇一択」と機械的に行動（CV）させる。

読後判断の候補（※これらは記事のH2で解説するのではなく、あくまで文末の「次への導線」として機能させる）:

- `売れる可能性がある`
- `残す・本人確認する`
- `自分で処分する`
- `買取不可後に処分先を選ぶ`
- `業者見積もりを検討する`
- `家族と話し合う`

記事タイプ別の役割:

- `実家整理ピラー`: 全体手順、売る・残す・処分の順番、家族確認の入口。
- `売れる物ピラー`: 捨てる前の価値確認、品目別記事へのハブ。
- `不用品処分ピラー`: 買取不可後、自治体処分、回収、見積もり判断のハブ。
- `心理・家族ピラー`: 共感から、勝手に捨てない、写真共有、本人確認、価値確認へ送る。
- `品目別記事`: その品目が査定対象になり得る条件、売れにくい条件、捨てる前チェック。
- `比較・判断記事`: 買取、回収、自治体、フリマ、出張/宅配などの使い分け。
- `商標記事`: Phase 2以降、実際の候補案件が固まってから、透明な仕組み説明と申込前注意点を書く。

## タイパ至上主義のUX（考えさせない・選ばせない）

現代人はタイパを求めています。「長文を読ませて、比較表を見せて、読者に選ばせる」という手法は認知負荷が高く離脱を招きます。読者には**「考えさせない、判断させない、選ばせない」**フローを設計します。

- **比較の放棄（一択の提示）**：「おすすめ5選」ではなく、メディアがリスクを背負って「あなたの状況ならこれ一択」と言い切る。
- **脳死できるアルゴリズム（作業）への変換**：「価値があるか判断しましょう」ではなく、「まずこれを箱に入れて送ってください。値段がつかなかったものだけ捨ててください」と、読者が考えずに手を動かせる手順に落とし込む。

## Scan Reader Design

読者は普通、記事をじっくり読まない。スクロールして必要な箇所だけ拾う前提で設計します。

全主力記事に検討する要素:

- 冒頭近くの `10秒判断ブロック`
- 読者状況別の分岐
- 判断表
- 捨てる前チェックリスト
- 文脈に合う内部リンク
- 将来CTAの置き場所

`10秒判断ブロック` の基本形:

1. 1から2文で結論を出す。
2. 2から3個の読者状況に分ける。
3. 各状況から該当H2または関連記事へ送る。
4. 高意図記事では、Phase 2以降に直接CTAを置ける余地を残す。

## CTA Strategy

CTAは「広告枠」ではなく、読者の判断が次に進む場所に置きます。

基本ルール:

- CTAは「フローチャート思考」で提示する。読者の「どの痛みから逃れたいか（ニーズ）」を条件分岐（例：「親と揉めたくない方」「明日ゴミを消し去りたい方」など）にし、それぞれの特効薬としての一択の業者を提示する。
- CTAは読者の痛みの限界点にそっと置く。
- 1記事1CTAではなく、ペインの分岐ごとに自然な出口（ショートカット）を置いてよい。
- 各分岐では絶対に迷わせない。1分岐1主CTA（一択提示）を基本にする。
- 内部リンクは導線の補助であり、必須の回遊ステップにしない。
- 記事単体でもCVし得る構造にする。

CTA密度:

- 高意図記事: 冒頭判断、判断表、該当H2、末尾に配置候補。
- 中意図記事: 10秒判断ブロック、該当H2、末尾に控えめに配置。
- 心理・家族記事: 直接案件より、価値確認・家族確認・処分判断への内部導線を優先。

各記事企画には、次のCTA設計を残します。

| 項目 | 内容 |
| --- | --- |
| conversion moment | 読者が次の判断をしたくなる瞬間 |
| placement | 冒頭、判断表、該当H2、末尾、モバイル固定など |
| destination type | 内部記事、比較記事、商標記事、案件LP |
| tracking name | 例: `top_decision_sellable`, `h2_recovery_estimate` |

## Phase Policy

現在の基本方針:

- Phase 1は、サイト基礎・ホームページ・カテゴリ・グロナビ・記事品質を整える期間。
- Phase 1でも既存記事に軽い案件リンクがある場合、機械的に剥がさない。
- ただし、過剰訴求、古い案件、読者の文脈に合わないリンク、広告色が強いリンクは整える。
- Phase 1の記事は、将来の収益CTA位置を内部の判断導線として運用する。
- Phase 2で、案件を比較選定し、商標記事とCTAを本格投入する。

Phase 1のCTA代替:

- 売れる可能性: `/sellable-disused-items/` や品目別記事へ送る。
- 量が多い・自力で無理: `/buying-vs-collecting/`, `/choose-waste-collector/`, `/how-to-dispose/` へ送る。
- 家族と揉めそう: `/family-issues/`, `/parent-wont-let-go-of-things/` へ送る。
- 買取不可: `/sell-or-dispose/` へ送る。

## Commercial Article Policy

商標記事は必要だが、最初から量産しない。

作る条件:

- 案件候補が実際に絞れている。
- 提携状況、成果地点、否認条件、対象エリア、電話連絡、LP UXを確認済み。
- 読者にとって申込前の不安解消になる。
- 比較・評判・口コミを名乗るなら、一次情報と引用範囲を守れる。

商標記事で許される切り口:

- 仕組み
- 向いている人、向いていない人
- 申込前の注意点
- 電話連絡や見積もりの流れ
- セイリ部式の適合チェック

商標記事で避けること:

- 実体験なしのレビュー
- 根拠のないおすすめ順位
- 口コミの水増し
- 報酬単価を読者向け評価に混ぜる

## Seiribu Fit Check

案件やサービスを記事内で扱うときは、読者向けに `セイリ部式・実家片付け適合チェック` を使えます。

評価軸:

- 物量への適合
- 対応範囲
- 連絡負担
- 比較しやすさ
- 条件の透明性

表現:

- `向いている`
- `条件付き`
- `確認必要`
- `対象外`

使わない表現:

- 根拠のない星評価
- 総合点ランキング
- 単価や成果条件を読者向け評価に混ぜた評価

## Case Selection

案件選定は読者適合と収益性を分けて見る。

読者向けに見る項目:

- 対象品目
- 対象エリア
- 電話連絡の有無
- 出張、宅配、持込、見積もりの負担
- キャンセルや費用の条件
- 家族トラブルを避けやすいか

内部で見る項目:

- 報酬単価
- 成果地点の遠さ
- 否認条件
- 承認率、EPCがあれば確認
- LPのわかりやすさ
- 商標・比較記事の可否

注意:

- 最新の提携状況、単価、成果条件はNotionとASP管理画面を正とする。
- 古いローカルメモだけで案件を確定しない。
- ウリエル、福ちゃん、バイセル、GoodDealなどの比較は別セッションで慎重に行う。

## Operating Workflow

記事方針を相談されたら、本文に入る前に次を確認します。

1. この記事の読者は誰か。
2. 読者は何に困っているか。
3. 読後に何を判断できるべきか。
4. その判断は、売る・残す・処分・見積もりのどれに近いか。
5. CTAを置くなら、読者のどの思考タイミングか。
6. Phase 1では内部導線で代替するか、既存案件リンクを軽く維持するか。
7. Phase 2で商標記事や案件CTAへ差し替える余地をどう残すか。

出力は短く、判断を先に出します。本文や長い構成案は書かず、必要なら `seiribu-seo-editor` のPHASE 0へ渡します。
