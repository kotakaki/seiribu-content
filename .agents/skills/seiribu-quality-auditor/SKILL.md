# Seiribu Quality Auditor

このスキルは、セイリ部の記事を「直すべきか」「どこを直すべきか」「直すと他記事とぶつからないか」を判断するために使います。本文の全文リライトは行わず、改善方針・優先度・具体的な修正箇所を整理します。

## 役割

- Googleの公式ガイドに沿って、有用性、信頼性、ユーザー第一、E-E-A-T、Who/How/Whyを確認する。
- 本文品質とは別に、主KW・ロングテール・検索者の生の言い回しを受け止める検索ラベルが残り、記事ごとのKW輪郭が尖っているかを確認する。
- セイリ部の読者にとって、記事が `売る・残す・捨てる` の判断に役立つかを見る。
- 他記事とのカニバリ、同一記事内のH2/H3重複、検索意図からの逸脱を見つける。
- 最新の法律、公的根拠、一次情報が必要な箇所を特定する。
- 禁止表現は機械的に消しすぎず、煽り・断定・虚偽だけを抑え、記事の感情や個性は残す。
- 改善に入る場合は `seiribu-seo-editor` のフェーズゲートへ渡す。

## 監査前に集めるもの

必要な範囲で確認します。

- 対象記事のURL、slug、title、H1、公開日、更新日、index状況。
- 公開中のtitle・H1・更新日と、監査対象の下書き又はリライト原稿が一致するか。違う場合、Search Consoleの実績を下書きの評価に使わない。
- 記事本文または下書きファイル。
- 主KW、準主KW、答えられる相談語、扱わないKW。リライトなら旧title、旧見出し、過去クエリも集める。
- Search Consoleのページ単位データ。クエリ一覧はページフィルタを先に掛け、直近28日と前28日、必要なら公開又はリライト以後の全期間で見る。
- Notionの対象行。既存の `優先度`、`処遇案`、`現在品質`、`リライト進捗`、`メモ`。
- 競合し得る自サイト記事のタイトル、slug、検索意図。
- 法律・制度・公的注意喚起が関係する場合の最新一次情報。

公的根拠やGoogle公式情報は、古い記憶で断定せず、必要なときにブラウズして確認します。

## Google観点の見方

Googleの公式資料をランキング要因リストとして扱わず、自己評価の観点として使います。

| 観点 | 確認すること |
| --- | --- |
| 有用性 | 読者が目的を果たすのに十分な情報を得られるか |
| ユーザー第一 | 検索流入目的ではなく、実家整理中の読者の判断に役立つか |
| 独自価値 | ただの一般論や他サイトの要約でなく、セイリ部式の判断・整理順・注意点があるか |
| 信頼性 | 情報源、法律、公的根拠、注意喚起、条件が明示されているか |
| E-E-A-T | 実体験がない部分を偽らず、編集メディアとして調査・比較・判断基準を示せているか |
| Who/How/Why | 誰が、どう作り、なぜこの読者のために書いたかが自然に伝わるか |
| 検索結果比較 | 同じ検索意図の他ページより、読者の次の行動が明確か |
| ページ体験 | 冒頭で迷わせず、表・チェックリスト・リンクが読みやすいか |
| KW輪郭 | 主KWと対象状況がtitle/H1・冒頭・主役H2で明確で、関連語の散布や抽象化で検索意図をぼかしていないか |

## KW輪郭と検索ラベル

品質が高くても、検索者が使う語とページの約束がつながらなければ、狙ったクエリの候補になりにくい。KW密度や関連語の個数は採点しない。

1. 検索の約束を1文で固定する。
   - 主KWを1つ、準主KWを最大3つまでに絞る。
   - 年齢、続柄、感情、行動、状況の語は、本文で答えられるものだけ相談語として残す。
   - 別記事の読後判断を求める語は `扱わないKW` にする。
2. 検索ラベルの置き場を確認する。
   - titleかH1に主KWと対象状況がある。
   - 冒頭で疑問に直接答え、抽象語だけに言い換えていない。
   - 主KW又は最重要の準主KWを処理する主役H2が1つある。
   - 相談語はH2/H3、FAQ、表、内部リンクのいずれかに自然な受け皿がある。
   - 内部リンクのアンカーが、送り先の判断を表している。
3. 0から15で補助評価する。
   - `ページの顔`、`冒頭の答え`、`構造の受け皿`、`ロングテール`、`役割の分離`を各0から3で見る。
   - 13から15は保持、9から12は最小補強、5から8は検索の約束を再設計、0から4は処遇再判定とする。

品質監査でKW輪郭が9点未満、旧版からのクエリ損失が疑われる、又はSearch Consoleのページ別クエリを使って復元箇所まで決める場合は、`seiribu-keyword-signal-auditor` を続けて使う。本文や見出しを変える場合は `seiribu-seo-editor` のPHASE 0へ渡す。

## セイリ部の品質基準

良い記事は、次のどれかを読者に渡します。

- 捨てる前に売れる可能性を確認できる。
- 本人や家族に確認すべき物を分けられる。
- 自治体処分、買取、不用品回収、フリマのどれに進むか判断できる。
- 家族と揉めずに整理を進めるための次の一歩がわかる。
- 不安を煽られず、費用・手間・安全面を現実的に比べられる。

品質を下げる兆候:

- 記事の主役が途中で変わる。
- 周辺トピックをすべてH2化している。
- 「選び方」「費用」「おすすめ」「法律」「買取順序」などが同じ記事内で主役化している。
- 読者の悩みに共感するだけで、実務判断へ進まない。
- 記事の質を上げる過程で、主KWや読者の生の言い回しが抽象語へ置き換わり、何の検索に答えるページか分からなくなる。
- 主KWを残そうとして、別トピッククラスタの関連KWをH2へ並べている。
- 根拠のない相場、ランキング、体験談、断定がある。
- 既存記事に任せるべき内容を長く説明している。

## カニバリ監査

記事同士の重複は、キーワードの一致だけで判断しません。検索意図、読者状況、読後判断で見ます。

1. 対象記事の主検索意図を1文で固定する。
2. 対象記事が答えるべき読後判断を1つから3つに絞る。
3. Notion、サイトマップ、既存下書きから類似slugを探す。
4. 類似記事ごとに、以下を比べる。
   - 主KW
   - 読者の状況
   - 記事の役割
   - 読後判断
   - CTAまたは内部リンク先
5. 重複を分類する。

| 分類 | 判断 | 対応 |
| --- | --- | --- |
| 共存 | 読者状況か読後判断が明確に違う | 内部リンクで役割を明示 |
| 軽い重複 | 一部H2だけがぶつかる | 該当H2を短縮し、相手記事へ送る |
| 強いカニバリ | 同じ検索意図に同じ結論で答えている | 片方を統合、ロングテール化、noindex候補 |
| 親子関係 | 一方がピラー、一方が詳細記事 | ピラーは要約、詳細は深掘り |

## 見出し内重複の監査

H2/H3ごとに役割を付けます。

- `主役`: 検索意図に直接答える。厚く書いてよい。
- `補助`: 判断を助ける。主役より短くする。
- `導線`: 別記事へ送る。詳説しない。
- `注意書き`: 誤解やトラブルを防ぐ。短く置く。
- `削除候補`: 主検索意図をぼかす。

重複の見つけ方:

1. 各H2の答えを1文で要約する。
2. 同じ答えが2回出ていないか見る。
3. 表で済む内容が複数H2に分散していないか見る。
4. H2タイトルだけ違って、本文が同じ判断を繰り返していないか見る。
5. `導線` や `注意書き` が独立記事のように肥大化していないか見る。

## 公的根拠・法律確認

法律、制度、安全、消費者トラブル、処分ルール、買取や訪問購入の注意点に触れる場合は、一次情報を優先します。

優先する情報源:

- 消費者庁
- 国民生活センター
- 環境省
- 経済産業省
- 自治体公式ページ
- 警察庁・都道府県警
- 家電リサイクル券センターなど制度運営主体
- Google Search CentralなどGoogle公式資料

確認ルール:

- 法律名、制度名、対象品目、罰則、手続き、日付が絡む場合は最新確認する。
- 自治体差があるものは全国一律のように断定しない。
- 公式情報で言える範囲と、セイリ部としての実務アドバイスを分ける。
- 根拠URLをメモまたは下書きに残す。
- 古い一次情報しか見つからない場合は、古いと明記して慎重に扱う。

## 表現チェック

禁止表現は、記事を無味乾燥にするためではなく、読者を誤誘導しないために見る。

強く直す表現:

- 絶対に高く売れる
- 必ず買取される
- どんな状態でも売れる
- 今すぐ申し込まないと損
- 実体験がないのに使ってみた
- 根拠のないランキング、相場、比較断定

残してよい表現:

- 読者の焦り、疲れ、不安への共感。
- `捨てる前に確認しておくと安心です` のような行動を促す言い方。
- `売れる可能性があります`、`査定対象になることがあります` のような条件付き表現。
- 体験談ではなく編集判断としての温度感。

直し方:

- 断定をすべて弱めるのではなく、根拠がある断定は残す。
- エモーショナルな導入は残し、危険な断定だけを条件付きにする。
- CTA周辺だけ広告色が強くなっていないか重点的に見る。
